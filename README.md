# 就活管理アプリ

就職活動で発生する企業情報、選考状況、締切、面接予定、ES、面接対策メモを一元管理するためのアプリです。

公開URL: https://shukatsu-tracker-nine.vercel.app

## 作成物の説明

就活では、企業ごとにマイページ、ES締切、面接日程、説明会、選考ステータス、志望度、提出内容などが分散しやすく、管理漏れが起きやすいという課題があります。

このアプリでは、企業ごとに以下の情報をまとめて管理できます。

- 企業名、志望度（最優先・高・中・低）、選考種別
- 本選考、インターン、早期選考などの分類
- 締切、面接、説明会などの予定
- 採用マイページURL、マイページID
- ESの質問と回答
- 回答文字数の自動カウント
- ESの字数目安・未記入チェックとAI添削（元の回答を残して添削案を追加）
- 企業メモ
- 気になる・応募済み・選考中・採用・不採用の5つの進捗（カードから直接変更・自動保存）
- 企業アイコン、企業公式サイトへのリンク
- バックアップと復元

PCとスマートフォンの両方で使えるクラウド同期版に加えて、Windows/Macでローカルに動かせる配布版も用意しています。

## 直面した課題と解決方法

### PCとスマートフォンで同じデータを使いたい

最初はブラウザ内の保存だけで動く形にしましたが、それだけでは別端末と同期できませんでした。

そこでSupabaseを導入し、ログインしたユーザーごとに企業情報、予定、ES、テンプレートをクラウド保存できるようにしました。

### 他のユーザーに使わせるときのプライバシー

就活情報には企業名、ES、面接メモなどの個人的な情報が含まれます。

そのため、Supabase側ではRow Level Securityを有効化し、ログイン中のユーザーが自分のデータだけを読み書きできる設計にしました。

また、クラウドを使いたくない人向けに、端末内だけにデータを保存するローカル版も用意しました。

### ESを実用的に管理したい

ESは単にメモとして保存するだけでは使いにくいため、質問と回答を分けて保存できるようにしました。

さらに、回答文字数を自動で表示し、ガクチカ、自己PR、志望動機などの使い回せる文章テンプレートを別ページで管理できるようにしました。

### 継続して使いたくなるUIにしたい

単なる管理表では使うモチベーションが下がるため、マスコットキャラクター、今日の格言、お祝い演出、落選時の励まし表示などを追加しました。

選考通過や内定のときには派手なお祝いを表示し、落選時には「なんて見る目のない企業なの！！」というメッセージを表示するようにしています。

### アーキテクチャ

フロントエンドはHTML、CSS、JavaScriptで構成しています。

クラウド同期版では、ブラウザからSupabaseに接続し、ログインユーザーごとにデータを保存します。SupabaseのRow Level Securityにより、ユーザーごとのデータ分離を行っています。

ローカル配布版では、Supabaseに接続せず、ブラウザのローカル保存を使って端末内にデータを保持します。これにより、サーバーへ就活情報を送らずに利用できます。

企業の追加・編集画面で企業名を入力すると、Wikidataの公開企業情報から公式サイトを探し、サイトのアイコンを候補として表示します。マイページの公開ドメインや、一部採用サービスの企業名部分を照合の手がかりに使います。候補が一意に絞れ、画像を読み込めた場合だけ自動設定します。同名企業など候補が複数ある場合は選択してください。設定後は企業情報を保存します。手動の画像URLは上書きしません。

AIの利用回数・APIキーは不要です。検索は公開版のAPIが必要ですが、公式サイトURLからの取得と保存済みアイコンの表示はローカル版でも使えます。検索対象は公開データに掲載された企業に限られ、画像が見つからない場合は頭文字表示を維持します。企業名をWikidataへ送信し、画像は候補サイトから直接読み込みます。マイページのID・パスワード・クエリは送りません。CSV・AI・バックアップに含まれる画像URLは引き続き取り込みません。

仕様参考: [Wikidata API](https://www.wikidata.org/wiki/Wikidata:Data_access), [サイトアイコン](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/link)。

## ローカル配布版

クラウド同期版とは別に、Windows/Macで使えるローカル配布版も作成しています。

ローカル配布版ではSupabaseに接続せず、就活データは利用者の端末内に保存されます。PCを買い替える場合や別端末へ移したい場合は、アプリ内のバックアップ・復元機能でJSONファイルを書き出して移行できます。

配布用zipはGitHub Releasesに添付して配布する想定です。

### AIメモ整理

ログイン中の利用者は、メモ帳の文章から企業カード案を作れます。UTF-8・Shift_JIS・BOM付きUTF-16のTXTを読み取り、会社見出しやESのQ/A表記を構造化してから、Cloudflare Workers AIのQwen3へ送ります。CSVはTXTとまとめて選択でき、貼り付け欄へ直接入れた場合も含めて端末内だけで解析し、AIへ送りません。Notionからコピーした表、または書き出したCSV・Markdownも同じ方法で取り込めます。企業名・系統・締切・インターン期間・ESリンク・マイページID・URLをカード項目へ対応付け、パスワードと保管場所の列は取り込みません。TXT・Markdown内のラベル付きマイページIDは、会社名を端末内で厳密に対応付けられる場合だけカード案へ戻し、AI送信文では伏せ字にします。メモ・ES・面接メモなどにラベル付きのパスワード、認証トークン、秘密鍵が紛れた場合も、カード作成前に伏せ字へ置き換えます。同じ企業名・選考区分の情報は1枚にまとめ、既存カードには空欄や未収録のメモだけを追加します。

TXTはブラウザとVercel Functionの両方で個人情報らしい箇所を伏せますが、完全な検出は保証できないため、送信前プレビューで確認し、個人情報や秘密情報は入力しないでください。元のTXT・CSVは保存しません。統合案はそのまま保存せず、通常の入力画面で確認・修正してから登録します。CSVだけの整理はAI利用回数を消費しません。

キャラクターを押すと「AIに相談」が開き、使い方や就活の相談に毎回AIが回答します。続けて質問でき、直近2往復だけを文脈として送ります。質問と会話はブラウザ・サーバー双方で伏せ字処理し、保存済みの企業・ES・アカウント情報は送りません。会話は画面を開いている間だけ保持し、「会話をリセット」、ログアウト、再読み込みで消えます。回答待ちにパネルを閉じても処理は続き、開き直して確認できます。ログインが必要で、AI相談・メモ整理・ES添削を合わせて1人1日30回までです。

### 実装方法

企業、予定、ES、テンプレートをJavaScript側で状態管理し、画面に反映しています。クラウド同期版ではSupabaseのテーブルに保存し、ローカル版では端末内の保存領域を使います。

バックアップ機能では、登録データをJSONファイルとして書き出し、別の環境で復元できるようにしています。同じ企業名・選考区分はIDが異なっても1枚へまとめ、既存内容を残したまま空欄と新しいメモだけを追加します。安全に収まらない長いメモがある場合は、黙って欠落させず復元を中止します。

## 個人情報への配慮

企業一覧は同じ企業名の選考を1枚の企業カードにまとめ、夏・冬インターン・早期選考・本選考を枝として表示します。「＋選考」で企業情報を引き継いだ空の選考を作り、ES・メモ・進捗は枝ごとに保存します。詳細上部から枝を切り替える際は編集中の内容を先に保存し、保存に失敗した場合は移動しません。絞り込み件数は企業数です。既存の未分類はボタン1つで夏インターンに移せます。移動は種類だけを書き換え、保存済みのES・メモ・進捗を残します。すでに同じ企業の夏インターンがある場合や別端末で更新された場合は上書きせずスキップします。CSV・AI取り込み・バックアップの記録単位は従来どおり会社名と選考種類の組を維持します。

企業一覧の「未設定アイコンを一括設定」で、ゴミ箱以外の全企業（結果済みを含む）の空欄を順番に検索できます。企業名とマイページURLの手がかり、登録済みなら公式サイトURLを使い、一意に絞れて画像を読み込めた場合だけ自動保存します。設定済みや途中で変更された企業は上書きしません。途中停止しても保存済みの分は残り、再実行は未設定分が対象です。候補なし・要確認の企業は、個別編集で公式サイトURLを補えます。AI利用回数は消費しません。

このリポジトリには、実際の就活情報、個人のES本文、ログイン情報、パスワードなどは含めていません。

Supabaseの公開用キーはフロントエンドで利用する前提のキーであり、データの閲覧・更新範囲はRow Level Securityで制御しています。

## セキュリティ面

- GitHubにはSupabaseの `service_role` key、データベースパスワード、個人のログインパスワードは含めていません。
- ブラウザ側に置いているのは、公開して使う前提のSupabase Publishable keyです。
- `entries` と `es_templates` の各テーブルではRow Level Securityを有効化し、`auth.uid()` と `user_id` が一致するデータだけを読み書きできるようにしています。
- `entries` では利用者・空白と英字大小をそろえた企業名・選考区分の一意制約を使い、別端末から同時保存しても重複カードが増えないようにしています。
- 未ログインユーザーや別ユーザーのデータは、RLSの条件に合わないため取得・更新できない設計です。
- 企業名、ES、メモなどの入力内容は、画面表示時にHTMLとして実行されないようにエスケープ処理をしています。
- Workers AIのAPIトークンはVercelの環境変数だけに保存し、ブラウザやGitHubへ公開しません。
